## 1. 背景与目标

当前知识库后端已完成 **PDF / PPT / Word** 解析落地（基于 MinerU 2.0 远程 HTTP API；Word/PPT 先经 LibreOffice 转 PDF），以及 JSON/CSV 内联解析。其余格式（Excel / TXT / Markdown / 图片）在 `FileParser` 中仍为 stub，上传后无法索引。

本设计的目标：

1. **扩展支持的文档格式**，覆盖上传层已接受的全部格式。
2. **统一输出结构**：所有格式解析结果对齐 MinerU 的 `struct_content.root` schema，使下游 `FileSplitterService` / `ElementInfo` / DB 写入链路零改动。
3. **统一抽象**：抽出 `BaseParser` / `OfficeToPdfParser`，各格式解析器继承实现，`FileParser` 仅做类型检测与路由。
4. **溯源优先**：对具备真实坐标的格式（PDF / Word / PPT / 图片）保留精确 bbox；对无坐标的格式合成语义坐标或置零，保证下游链路字段一致。
5. **转换 PDF 持久化**：Word/PPT（及后续图片）转换产物上传 MinIO，供前端按 PDF 链路预览与 bbox 高亮。

## 2. 统一目标结构（MinerU Schema）

所有解析器必须返回如下形状的 Dict：

```python
{
    "status": "success",
    "total_pages": int,
    "struct_content": {
        "root": [
            {
                "page_idx": int,                          # 0-based 页码
                "page_size": {"width": float, "height": float},
                "page_info": [                            # 该页元素列表
                    {
                        "id": str,                        # UUID
                        "element_index": int,             # 页内序号，从 0 开始
                        "type": "text" | "image" | "table" | "equation",
                        "page_idx": int,
                        "bbox": [x0, y0, x1, y1],         # 0~1000 归一化，左上角原点；无坐标时 [0,0,0,0]
                        # type-specific 字段：
                        "text": str, "text_level": int,                # text
                        "img_path": str, "image_base64": str,          # image
                        "image_caption": list, "image_footnote": list,
                        "table_body": str(html), "table_caption": list, "table_footnote": list,  # table
                        "text_format": "latex"                         # equation
                    }
                ]
            }
        ]
    },
    "content": str  # 全文 markdown（可选）
}
```

**元素类型**遵循 `ElementType` 枚举（`src/types/models/parse_result.py:22-28`）：`text` / `image` / `table` / `equation` / `discarded`。

**bbox 坐标系**：0~1000 归一化，左上角为原点，与 MinerU 一致。无视觉坐标的格式统一置 `[0,0,0,0]`，下游通过 `page_idx` + `element_index` 做结构化溯源。

## 3. 整体架构

### 3.1 BaseParser / OfficeToPdfParser（已落地）

`base_parser.py` 已新增，包含两层抽象：

1. **`BaseParser`**：统一 `parse()` 接口 + `_build_element` / `_build_page` / `_wrap_result` 辅助方法。
2. **`OfficeToPdfParser(BaseParser)`**：Word/PPT 共用「LibreOffice 转 PDF → `PDFParser`(MinerU)」链路。

**与初稿差异**：`parse` 采用**实例方法**（非纯 static），以便注入 `Mineru2Client`、`soffice_path` 等依赖，匹配现有 `PDFParser` DI 模式。

```python
class BaseParser(ABC):
    """通用文档解析器基类，所有格式解析器继承此类。"""

    @abstractmethod
    async def parse(self, file_path: Union[str, Path], file_name: Optional[str] = None) -> Dict:
        """解析文档，返回 MinerU schema 形状的 Dict。"""
        ...

    @staticmethod
    def _build_element(element_type, page_idx, element_index, bbox=None, **kwargs): ...

    @staticmethod
    def _build_page(page_idx, page_info, page_size=None): ...

    @staticmethod
    def _wrap_result(root, content="", total_pages=None): ...


class OfficeToPdfParser(BaseParser):
    """Word/PPT 共用：LibreOffice → PDF → MinerU。"""

    def __init__(self, mineru_client, source_file_type, ..., soffice_path="soffice", convert_timeout=120):
        ...

    async def parse(self, file_path, file_name=None) -> Dict:
        pdf_path = await self._convert_to_pdf(file_path)
        # MinerU 按扩展名选解析器：必须传 .pdf（传 .doc/.ppt 会 markdown 有内容但 content_list 为空）
        result = await PDFParser(...).parse(pdf_path, f"{Path(file_name).stem}.pdf")
        result["file_type"] = self.source_file_type
        # 成功时把临时 PDF 所有权交给上层持久化（失败仍由本层清理）
        result["converted_pdf_temp_path"] = str(pdf_path)
        return result
```

### 3.2 FileParser 路由

`FileParser.parse()` 维持现有路由结构，各 `_parse_<type>()` 方法改为实例化对应 `BaseParser` 子类并调用 `parse()`。`SUPPORTED_EXTENSIONS` 扩展加入图片格式。

```
FileParser.parse(file_path)
    ├─ detect_file_type(suffix)           # 扩展名 → 内部类型
```

## 4. 各格式解析方案

### 4.1 Word（`.docx` / `.doc`）— 转 PDF + MinerU

**策略**：Word 文档为流式排版，无可靠视觉 bbox，溯源能力弱。为获得与 PDF 一致的精确坐标与版式结构，统一**先转换为 PDF，再走 MinerU 解析链路**。

**转换方式**：

- 使用 LibreOffice headless 模式转换：
  ```bash
  soffice --headless --convert-to pdf --outdir <tmp_dir> <input.docx>
  ```
- `.doc`（旧二进制格式）同样通过 LibreOffice 转换，无需单独解析逻辑。
- 转换后复用 `PDFParser.parse()` 完成解析，输出结构天然与 PDF 一致。
- **提交 MinerU 的文件名必须为 `.pdf`**（`OfficeToPdfParser` 将 `file_name` stem + `.pdf`）；若仍传 `.doc`，会出现 markdown 有内容但 `content_list` 为空、总页数=0。
- **转换 PDF 上传 MinIO 路径与原生 PDF 一致**：`{user}/{session}/{folder}/{file_id}.pdf`（见 §4.7）。

**实现要点（已落地）**：

```python
class WordParser(OfficeToPdfParser):
    def __init__(self, mineru_client, ..., soffice_path="soffice", convert_timeout=120):
        super().__init__(
            mineru_client=mineru_client,
            source_file_type="word",
            display_name="Word",
            ...
        )
```

- `FileParser._parse_word()` 与 PPT 对齐：注入 `Mineru2Client` + `[libreoffice]` 配置。
- 成功解析后结果携带 `converted_pdf_temp_path`，由 `FileParserService` 上传 MinIO。

**依赖**：运行环境需安装 `libreoffice`（Docker 镜像中加 `apt-get install libreoffice`）。

**溯源能力**：精确视觉溯源（继承 PDF 的真实 bbox；前端渲染转换后 PDF）。

### 4.2 图片（`.png` / `.jpg` / `.jpeg` / `.gif` / `.webp` / `.svg` / `.bmp`）— 转 PDF + MinerU

**策略**：图片无文本结构，需 OCR 提取文本与坐标。MinerU 2.0 原生支持图片输入（`method=ocr`），输出结构与 PDF 一致。为统一链路、复用现有 `Mineru2Client`，采用**先合成单页 PDF，再走 MinerU**的方式（也可直接将图片作为 MinerU 输入，取决于 MinerU API 对图片的支持情况）。

**两种实现路径**：

| 路径 | 说明 | 优劣 |
|---|---|---|
| A. 图片直接送 MinerU | 若 MinerU API 接受图片输入，直接调用 | 最简单，零转换开销 |
| B. 合成单页 PDF 再 MinerU | 用 `reportlab` / `Pillow` 将图片嵌入单页 PDF，再走 `PDFParser` | 兼容性最好，保证 MinerU 一定能处理 |

**推荐**：优先路径 A（若 MinerU 支持图片）；fallback 路径 B（合成 PDF）。

**实现要点（路径 B）**：

```python
class ImageParser(BaseParser):
    @staticmethod
    async def parse(file_path, file_name=None):
        pdf_path = await _image_to_single_page_pdf(file_path)  # reportlab/Pillow
        # 与 Word/PPT 相同：MinerU 按扩展名选解析器，必须传 .pdf
        result = await PDFParser.parse(pdf_path, f"{Path(file_name).stem}.pdf")
        result["file_type"] = "image"
        return result
```

**`FileParser` 改造**：`SUPPORTED_EXTENSIONS` 新增图片扩展名映射到 `image` 类型，路由分支新增 `image`。

**溯源能力**：精确视觉溯源（OCR 真实 bbox，可在原图上高亮文本块）。

### 4.3 Excel（`.xlsx` / `.xls`）— openpyxl

**策略**：Excel 是结构化表格数据，原生有 Sheet（页）+ 行列坐标，契合设计文档「Sheet Name = 段落标题」模型。使用 `openpyxl` 直接提取，保留表格语义。

**解析库**：`openpyxl`（`.xlsx`，只读模式 `read_only=True`）；`.xls` 用 LibreOffice 转 `.xlsx` 后再解析。

**映射规则**：

| MinerU 字段 | Excel 映射 |
|---|---|
| `page_idx` | Sheet 索引（0-based） |
| `page_size` | `{width: max_column, height: max_row}` |
| 段落标题元素 | Sheet 名 → `text` 元素，`text_level=1`，`bbox=[0,0,0,0]` |
| `table` 元素 | 有效数据区域（或合并单元格区域）转 HTML 表格作为 `table_body` |
| `bbox` | `[row_start, col_start, row_end, col_end]` 按 sheet 维度归一化到 0~1000 |
| `content` | 各 sheet 转 markdown 表格拼接 |

**大表处理**：单个 sheet 行数过多时，按 N 行（如 100 行）切块为多个 table 元素，避免单元素过大。

**图表**：`openpyxl` 可检测 chart 对象但无法渲染图片。首期方案：检测到 chart 时标记为 image 元素并跳过渲染（`img_path` 留空）；后续可考虑 LibreOffice 转 PDF 提取图表图片。

**实现要点**：

```python
class ExcelParser(BaseParser):
    @staticmethod
    async def parse(file_path, file_name=None):
        wb = openpyxl.load_workbook(file_path, read_only=True, data_only=True)
        root = []
        for sheet_idx, ws in enumerate(wb.worksheets):
            page_info = [_build_sheet_title_element(ws.title, sheet_idx)]
            page_info += _extract_table_elements(ws, sheet_idx)  # 区域 → HTML table
            root.append(BaseParser._build_page(sheet_idx, page_info, _sheet_size(ws)))
        return BaseParser._wrap_result(root, _to_markdown(root))
```

**溯源能力**：结构化溯源（定位到具体 Sheet + 单元格区域，可高亮单元格）。

### 4.4 PPT（`.pptx` / `.ppt`）— 转 PDF + MinerU

**策略**：为获得与 PDF 一致的精确像素 bbox 与版式结构（文本框、表格、图片、公式的精确位置），PPT 统一**先转换为 PDF，再走 MinerU 解析链路**。这样 PPT 的溯源能力与 PDF 完全一致，无需自行处理 EMU 坐标归一化、shape 类型识别、组合形状递归等复杂逻辑。

**转换方式**：

- 使用 LibreOffice headless 模式转换：
  ```bash
  soffice --headless --convert-to pdf --outdir <tmp_dir> <input.pptx>
  ```
- `.ppt`（旧二进制格式）同样通过 LibreOffice 转换，无需单独解析逻辑。
- 转换后复用 `PDFParser.parse()` 完成解析，输出结构天然与 PDF 一致。
- **提交 MinerU 的文件名必须为 `.pdf`**（`OfficeToPdfParser` 将 `file_name` stem + `.pdf`）；若仍传 `.ppt`/`.pptx`，会出现 markdown 有内容但 `content_list` 为空、总页数=0。
- **转换 PDF 上传 MinIO 路径与原生 PDF / Word 一致**：`{user}/{session}/{folder}/{file_id}.pdf`（见 §4.7）。

**跨平台 soffice 路径配置**（开发环境 macOS / 生产环境 Ubuntu Linux）：

```python
# config/config.toml
[libreoffice]
# macOS 开发环境
soffice_path = "/Applications/LibreOffice.app/Contents/MacOS/soffice"
# Ubuntu 生产环境（Docker 镜像 apt-get install libreoffice 后）
# soffice_path = "soffice"
convert_timeout = 120  # 转换超时（秒）
```

通过 env / config 注入 `soffice_path`，代码跨环境运行无需改动。

**实现要点（已落地）**：

```python
class PPTParser(OfficeToPdfParser):
    def __init__(self, mineru_client, ..., soffice_path="soffice", convert_timeout=120):
        super().__init__(
            mineru_client=mineru_client,
            source_file_type="ppt",
            display_name="PPT",
            ...
        )
```

- LibreOffice 转换使用独立 `UserInstallation` profile，避免并发 profile 锁。
- 成功解析后结果携带 `converted_pdf_temp_path`，由上层持久化。

**转换产物持久化（已落地）**：见 §4.7。转换 PDF 上传 MinIO 后写入 `workspace_file_system.ext_attributes`；`/raw` `/preview` 默认返回转换 PDF，`source=original` 可取原始文件。

**依赖**：运行环境需安装 `libreoffice`：
- macOS 开发：`brew install --cask libreoffice`
- Ubuntu 生产（Docker）：`apt-get install -y libreoffice`

**溯源能力**：精确视觉溯源（继承 PDF 的真实像素 bbox，前端渲染转换后 PDF 并高亮区域）。

### 4.5 TXT（`.txt`）— 纯 Python

**策略**：纯文本无结构、无坐标。按段落（空行分隔）切分为多个 text 元素，整文件作为 1 页。

**解析库**：Python 标准库，无需第三方依赖。

**映射规则**：

| MinerU 字段 | TXT 映射 |
|---|---|
| `page_idx` | 0（整文件 1 页） |
| `page_size` | `{width: 0, height: 0}` |
| `text` 元素 | 每个段落（空行分隔）= 1 个 text 元素 |
| `text_level` | `None`（纯文本无标题层级） |
| `bbox` | `[0, 0, 0, 0]` |
| `content` | 原文 |

**大文件处理**：段落过长时，由下游 `TextSplitterService` 的长度兜底策略处理，解析层不做额外切分。

**实现要点**：

```python
class TxtParser(BaseParser):
    @staticmethod
    async def parse(file_path, file_name=None):
        text = Path(file_path).read_text(encoding="utf-8", errors="replace")
        paragraphs = [p.strip() for p in re.split(r"\n\s*\n", text) if p.strip()]
        page_info = [
            BaseParser._build_element("text", 0, idx, text=p)
            for idx, p in enumerate(paragraphs)
        ]
        root = [BaseParser._build_page(0, page_info)]
        return BaseParser._wrap_result(root, text)
```

**溯源能力**：弱溯源（仅文档级 + 段落序号，无视觉坐标）。

### 4.6 Markdown（`.md` / `.markdown`）— markdown-it-py

**策略**：Markdown 本身结构化（标题层级、代码块、表格、图片、公式），使用 `markdown-it-py` 解析为 token 流后映射到 MinerU schema，几乎无损保留语义。

**解析库**：`markdown-it-py`（纯 Python，CommonMark + GFM，支持 table / code_block / image / heading 等 token）。

**映射规则**：

| MinerU 字段 | Markdown 映射 |
|---|---|
| `page_idx` | 每个 H1（`#`）= 一页，其下内容为该页元素；无 H1 时整文档 = 1 页 |
| `page_size` | `{width: 0, height: 0}` |
| `text_level` | heading token 的层级：`#`=1, `##`=2, `###`=3 |
| `text` 元素 | heading（带 text_level）/ paragraph / code_block |
| `image` 元素 | `![]()` → 提取图片路径，下载/复制后上传 MinIO，填 `img_path` |
| `table` 元素 | GFM table → 转 HTML `table_body` |
| `equation` 元素 | `$$...$$` 代码块 → `text_format=latex` |
| `bbox` | `[0, 0, 0, 0]` |
| `content` | 原文即为 markdown，直接作为 `content` |

**实现要点**：

```python
class MarkdownParser(BaseParser):
    @staticmethod
    async def parse(file_path, file_name=None):
        md_text = Path(file_path).read_text(encoding="utf-8")
        tokens = MarkdownIt().enable("table").parse(md_text)
        root = _tokens_to_pages(tokens)  # 按 H1 切页，token → element
        return BaseParser._wrap_result(root, md_text)
```

**溯源能力**：结构化溯源（定位到章节标题 + 段落，可在源 .md 中按文本匹配定位）。

### 4.7 转换 PDF 持久化与预览链路（Word / PPT，已落地）

Word/PPT 解析成功后，不再丢弃临时 PDF，而是走完整持久化链路，供前端按 PDF 视图做 bbox 高亮：

```
OfficeToPdfParser.parse()
  → result["converted_pdf_temp_path"] = <临时 PDF>
  → FileParserService._persist_converted_pdf_if_needed()
       ├─ 可选线性化（fast web view）
       ├─ StorageManager.upload_converted_pdf()
       │    → {user}/{session}/{folder}/{file_id}.pdf  （与 raw PDF 同规则）
       └─ result["converted_pdf_storage_path"] = bucket/object_path
  → ParseResult.document_metadata["converted_pdf_storage_path"]
  → FileParserWorker 回写 workspace_file_system.ext_attributes:
       {
         "converted_pdf_storage_path": "...",
         "render_as": "pdf"
       }
```

**API 行为**：

| 接口 | 行为 |
|---|---|
| `GET /api/knowledge/file/{file_id}/raw?source=auto` | Word/PPT **默认返回转换 PDF**（`Content-Type: application/pdf`） |
| `.../raw?source=original` | 强制返回原始 Office 文件 |
| `.../raw?source=converted` | 强制返回转换 PDF；不存在则 404 |
| `GET /api/knowledge/file/{file_id}/preview` | 预签名 URL 同样优先转换 PDF；响应增加 `render_as` / `preview_mime_type` / `has_converted_pdf` |

**注意**：旧文件若在本能力上线前已解析，`ext_attributes` 中无转换 PDF 路径，需**重新解析**后才能预览/溯源。

## 5. 溯源能力总览

溯源（source tracing）能力取决于解析结果能否提供精确的定位坐标（`page_idx` + `bbox`）。

| 格式 | 解析方式 | page_idx | bbox | 溯源等级 |
|---|---|---|---|---|
| PDF | MinerU | 真实页码 | 真实 0~1000 | 精确视觉溯源 |
| Word | 转 PDF + MinerU | 真实页码 | 真实 0~1000 | 精确视觉溯源 |
| 图片 | 转 PDF + MinerU | 单页 | OCR 真实 bbox | 精确视觉溯源 |
| PPT | 转 PDF + MinerU | 真实页码 | 真实像素 bbox | 精确视觉溯源 |
| Excel | openpyxl | Sheet 索引 | 行列归一化 | 结构化溯源（单元格级） |
| Markdown | markdown-it-py | H1 切页 | 无 | 结构化溯源（章节段落级） |
| TXT | 纯 Python | 单页 | 无 | 弱溯源（文档级 + 段落序号） |

**结论**：PDF / Word / 图片 / PPT 四条链路均具备精确视觉溯源能力（前端可高亮原文区域）；Excel / Markdown 为结构化溯源（定位到单元格或章节）；TXT 溯源能力最弱。

## 8. 待确认 / 未决事项

1. **MinerU 是否支持图片直接输入**：决定图片走路径 A（直接送 MinerU）还是路径 B（合成 PDF）。需查阅 MinerU 2.0 API 文档或实测。
2. **LibreOffice 转换的并发与性能**：已用独立 `UserInstallation` 缓解 profile 锁；高吞吐仍可能需要进程池或预转换队列。
3. **Excel 图表渲染**：首期跳过，后续是否需要可视化图表（影响是否引入 LibreOffice 转 PDF 辅助）。
4. **`parse_tool` 字段**：当前仍硬编码 `parse_tool="mineru"`，需按实际格式区分（如 `mineru` / `openpyxl` / `markdown-it`）。Word/PPT 经「转 PDF + MinerU」后可记为 `mineru`，原始格式已写入 `file_type` / `document_metadata`。
5. **已确认并落地**：Word/PPT 溯源渲染对象为**转换后 PDF**（`/raw` 默认下发；`source=original` 取原件）。
